# Can a learned model pick more CS2 Match winners than the anchor? (phase 2: HLTV features)

## Primary configuration (declared before its evaluation)

Written and committed before any model was evaluated on the HLTV features. Phase 1's baseline
table (`ml-notes/ml-core.md`) had been seen, on these same Matches: logreg was the most accurate
there, which informed the choice.

- **Model:** `logreg` (L2 logistic regression, C chosen by inner walk-forward on training Events
  only, both team orientations).
- **Features:** `full` = phase 1's `baseline` groups plus every HLTV group: `rank`, `opp_form`,
  `past_form`, `hltv_h2h`, `players`, `map_pool`, `sides`, `standin`, `roster`, `stakes`.
- **Data:** research archive snapshot 2; evaluated on the 2087 in-scope Matches with an anchor
  (tier S/A, no qualifiers), walk-forward by Event exactly as phase 1.
- **Question and rule:** the difference in accuracy (share of winners picked) model − anchor on the
  same Matches. The model "picks more winners" only if the 90% Event-bootstrap interval (2000
  resamples, seed 33) lies wholly above zero.

Everything else below (the other models, the ablations, log-loss, importance) is exploratory: many
comparisons are made, and some will look good by chance.

## Conclusion (written after the run)

**No.** The primary configuration (logreg on every feature) picks 65.4% of winners against the
anchor's 65.8% on the same 2087 Matches: −0.4 pp [−1.5, +0.6]. No model and no single added HLTV
group picks measurably more winners: of 36 configurations (plus four map-model runs) none has an
accuracy interval wholly above zero; the best point estimate, logreg + `map_pool`, is +0.5 pp
[−0.5, +1.5], which is what chance among this many comparisons looks like. Several are measurably
worse (mlp on all features −2.3 pp; lgbm on the tier S slice −2.0 pp).

What the models do learn is the known fix of the overconfident Valve rating: log-loss falls from
0.794 to about 0.64 to 0.66, the same gain `learned_weights` / `rating_calibration` show in the Rust
lab, and logreg on the anchor's own inputs alone already gets it (phase 1). The HLTV features do not
improve on that: the best log-loss is logreg + `map_pool` at 0.6417 against 0.6442 for the
baseline. LightGBM leans on the HLTV rank (`rank_log_ratio` 24% of gain), but the rank only
restates what the market and the Valve rating already say about who is stronger, and it does not
flip any extra picks to the right side.

Plain reading for KallBet: with these data (≈2100 scored Matches, a third with a market line), the
anchor's pick is as good as any learned pick measured here. The open hope is more data: the wider
archive (tier B and 2023-2024 Events as training rows) is not ready yet; see below.
